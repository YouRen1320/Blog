## 关键决策

### 1. 改密码不强制踢人,只提示
换密码后**保留当前 JWT 有效**而不是把所有 session 失效。理由:
- 失效要么改 JWT 加 jti 黑名单(成本高),要么轮转 secret(全员重登,影响大)
- 单人博客,用户 ≈ 自己,失效收益小
- UI 层提示"建议在所有设备重新登录",把决策交还给人

### 2. backfill 串行而非并发
BGE 在 ai-service 单实例上跑,并发请求只是**排队 + 占内存**,没真加速。串行还能简化错误处理(每篇独立 try/catch)+ 限制并发对 DB 的影响。

### 3. backfill 同步处理而非任务队列
当前文章数极少(1 篇)。同步同一个 HTTP 请求里跑完,前端 timeout 给 5 分钟。如果未来文章数到 100+,改成 BullMQ 异步任务 + SSE 进度推送是直接的演进路线,但**现在不做**。

### 4. LangSmith 走环境变量,不引代码
LangGraph 的 `langchain-core` 自动检测 `LANGCHAIN_TRACING_V2`。开关控制权完全在 ops,代码无侵入。**关闭时性能 0 影响,开启时不需要 redeploy**。

### 5. 改密码 endpoint 走 `/auth` 而不是 `/admin/auth`
任何认证用户都能改自己密码(future user 角色也能用),不是 admin 特权。挂在 `/auth/password` 跟 `/auth/login` `/auth/profile` 一致。

## 踩坑

1. **`articles.controller` 多注 `EmbeddingService`,但模块声明里没显式 imports**:`EmbeddingModule` 是 `@Global()`,可以直接注入。新人容易以为要在 ArticlesModule 加 imports,实际不需要。
2. **路由顺序**:`@Post('backfill-embeddings')` 必须放在 `@Patch(':id')` 等动态参数路由之前(虽然 method 不同没冲突,但按"具体路径在前"原则更稳)。
3. **服务器 git pull 又超时**:GitHub 在境内对长链接非常飘,改用 `tar | scp | tar -xzf` 同步改动文件(只 33KB)秒到。
4. **prettier 自动重格式化未追踪文件**:跑 jest 时 IDE / hook 顺手 prettier 把一堆历史文件格式化了。功能等价但 diff 嘈杂,**单独提一个 `chore: prettier format` commit** 不混进 feature。
