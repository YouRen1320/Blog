# docs/ —— 开发日志 + 学习材料

这个目录不是代码注释的搬运,而是**开发过程的复盘**。

目标读者是项目作者本人(以及未来想从零做一遍的你),所以重点不是"代码怎么写",而是:

- **为什么做这个决定** —— 备选方案是什么,凭什么选这个
- **踩过什么坑** —— 实际跑代码时遇到的问题和解决思路
- **如果再做一次会怎么调** —— 学到的教训

> 代码本身能告诉你"做了什么",这里告诉你"为什么这么做"。

## 文档约定

### Journal(每个任务一份)
固定结构,方便对照:

1. **目标** —— 这个任务要交付什么,完成标准是什么
2. **关键决策** —— 在这个任务里做了哪些选择,为什么
3. **实际做了什么** —— 主要改动,带文件路径
4. **踩坑 / 注意** —— 实际操作中遇到的问题
5. **验收记录** —— 跑了什么命令,看到什么结果
6. **给学习者的提醒** —— 自己重做容易忽略的点

### Decisions(ADR)
当某个决定**影响多个任务/版本**(例如选 JWT vs Session、Caddy vs Nginx),写成单独 ADR,journal 里链接过去就行,避免重复。

ADR 格式:
- **背景** —— 当时面临什么问题
- **选项** —— 备选方案 + 各自利弊
- **决定** —— 选了哪个
- **后果** —— 这个选择带来的连锁影响

## 阅读建议

如果你是从零开始想跟着做:

1. 先看 `00-roadmap.md` 了解整体阶段划分
2. 跟着 journal 顺序读(V1-01 → V1-02 → ...)
3. 看到 journal 引用某个 ADR 时,跳过去读那个决策的来龙去脉
4. 每读完一个 journal,先自己想想"如果是我会怎么做",再对照看选了什么、为什么
