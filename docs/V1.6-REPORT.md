## 关键决策

### 1. ADMIN 不开放注册

公开 `POST /auth/register` 永远创建 USER。ADMIN 升级路径预留:

- 短期:数据库 SQL 直改(单管理员博客 ADMIN 只一两个)
- 中期:加 `/admin/users` CRUD 页面 ADMIN 可改 role(留 v1.7+)

### 2. ownership 在 service 层,不靠 guard

考虑过加 `@OwnsArticle()` decorator + `OwnershipGuard` —— 但 guard 拿不到 article 数据(需要 fetch),会双倍查库。直接在 service 层 `assertOwnership(id, user)` 一次查,精准且简单。

### 3. admin sidebar 改顶栏(不是抽屉)

抽屉(hamburger 按钮 + 滑出 panel)是手机标准,但本博客 admin 导航只有 7 个 item,**横排滚动够用**。少一层交互(点击 hamburger → 展开),用户找 nav 直接看到。

### 4. < 480 隐 logo + user 信息

极窄屏(< 480px)宽度 ~360-440px,放 220 sidebar item 直接挤死。logo 是装饰,user 信息只在 settings 用得到,隐了节省横向空间。

## 踩坑

按时间顺序:

1. **服务器磁盘 99% 满**:V1.4 多次 build 累积 + 4GB swap + buildkit cache,只剩 496MB free,ai-service build 直接卡。处理:
   - 删 swap 4GB
   - `docker buildx prune -af` 清 buildkit cache
   - `docker system prune -af --volumes` 释放 22.44 GB(pgdata 因为 named volume 保护没被勒)
   - 之后磁盘 99% → 30%,内存 87% → 45%,SSH 连接恢复
2. **`docker buildx prune` 占内存把 sshd 挤进 swap**:服务器 banner exchange 卡 10+ 分钟。教训:小内存(2GB)ECS 不要并发跑 prune + build,**一次只跑一个高负载操作**
3. **Aliyun Linux 不是 Debian**:`apt-get clean` 找不到命令(这是 Anolis OS,用 yum)
4. **多个 hung SSH 进程占 sshd MaxStartups slot**:每次卡死后 `pkill -9 -f "ssh.*blog-deploy"` 清干净再重连
5. **V1.6 service 签名变了 spec 挂 3 个**:publish/unpublish 加了 user 参数,旧 spec 不传报错。修法:加 ADMIN_USER 常量 + 新增 1 个 USER → ForbiddenException 测,17/17 通
