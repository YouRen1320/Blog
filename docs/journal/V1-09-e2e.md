# V1-09 端到端测试

**日期**:2026-05-05
**任务**:#9
**状态**:已完成

## 目标

跨 admin + web 跑一条主链路:登录 → 新建 → 发布 → web 验证 → 删除 → 验证消失。这是确认 V1 真正完整的最后一道关。

**验收**:`pnpm e2e` 三个测试全绿。

## 关键决策

### 1. Playwright,不是 Cypress

**备选**:Cypress(更老牌,UI runner 漂亮)
**已选**:Playwright

理由:
- Playwright 是 Microsoft 出品,跟 VS Code / TypeScript 生态对齐
- 多浏览器引擎(Chromium / Firefox / WebKit)原生支持
- 速度更快,API 更现代(async/await 一等公民)
- v1.59+ 自带 webServer 多服务编排,一个配置启全栈
- 社区 momentum 在 Playwright 这边

### 2. e2e 放根目录,不是某个 app 内

测试同时跨 admin + web,放任何一个 app 都不合适。**根目录 `e2e/`** 是中立位置。

### 3. webServer 用 reuseExistingServer

```ts
webServer: [
  { command: 'pnpm --filter api start:prod', reuseExistingServer: true },
  { command: 'pnpm --filter admin dev', reuseExistingServer: true },
  { command: 'pnpm --filter web preview', reuseExistingServer: true },
]
```

含义:Playwright 检测到已有服务跑在那个端口就直接用,否则自动启动。本地开发跟 CI 用同一份配置,**手动验证 + 自动跑测**两不误。

### 4. 严格串行(workers: 1)

e2e 测试共享同一个 Postgres。多 worker 会互相洗数据,同时操作同一篇文章会冲突。
代价:跑一遍要 ~20 秒。但 V1 三个测试,可接受。
未来:每个测试 worker 用独立 schema(prisma 支持),可以并行。

### 5. 时间戳 slug,避免和残留数据冲突

```ts
const stamp = Date.now()
const ARTICLE_SLUG = `e2e-test-${stamp}`
```

测试不依赖"先清空再插入",而是**用唯一 key**避开残留。坏处:多次跑会留下垃圾数据。**db:seed 用 upsert 不删旧数据**,这种垃圾会累积。Final 阶段加个 `db:clean-e2e` 脚本就行。

## 踩坑 / 注意

### 坑 1:Vite 默认端口 5173,但被占就漂到 5174
本地多次跑 dev,有时端口被前一次占用,vite 偷偷跳到 5174。然后 e2e 配置写的 5173,连不上。
**修法**:apps/admin 已有 `vite.config.ts` 显式 `server.port: 5174 + strictPort: true`(占用就报错而不是漂走),playwright 配置也改成 5174。**严格端口胜过自适应**。

### 坑 2:Playwright 严格模式下 `h1` 匹配多个元素
文章详情页 `<h1 class="cn title">` + markdown 渲染的 `<h1>E2E</h1>` 都是 h1。Playwright 默认严格模式抛错。
**修法**:用更精确的选择器 `h1.title`(只匹配页面标题)。

### 坑 3:等 `text=PUBLISHED` 是误报陷阱
我一开始让 publish 后等 `text=PUBLISHED` 出现。但 Editor.vue 的 meta-info 里有一行 "PUBLISHED:" 作为标签,**任何状态下都可见**。所以 click 没生效,测试也"通过"了 publish 这一步。
**修法**:等"下线"按钮出现 —— 这只在 status === 'PUBLISHED' 时才渲染,语义和 UI 强绑定。
**教训**:**不要等 textually present 的内容,要等 conditionally rendered 的内容**。

### 坑 4:webServer timeout 默认 60s 不够 build 完
第一次跑 e2e 时 web preview 没 build 过,webServer 试图启动 `nuxt preview` 但找不到 `.output/` → 超时退出。
**修法**:跑 e2e 前先 `pnpm --filter web build`。或者 webServer command 写成 `nuxt build && nuxt preview`(慢但稳)。

### 坑 5:原生 confirm 需要预注册 listener
admin 删除按钮触发 `window.confirm(...)`。Playwright 默认会让 dialog 自动 dismiss。要主动 accept:
```ts
page.on('dialog', (dialog) => dialog.accept())
```
**注意**:这个 listener 必须在触发 dialog 的 click **之前**注册,否则错过事件。

### 坑 6:DB 重置的 AI 防护
跑测试前想 `pnpm db:reset` 一下让 DB 干净,但 Prisma 6.19 的 AI agent 防护会拒绝执行。改用 `pnpm db:seed`(upsert),数据会累积但能用。**Final 阶段写一个 `db:clean-e2e`** 专门清 e2e 残留(slug LIKE 'e2e%' 的)。

## 给学习者的提醒

- **e2e 是最后的保险,不是第一道关**。先靠 unit 测确保单点对,再靠 e2e 确保接起来对。否则 e2e 失败不知道是哪一层错。
- **Playwright 的选择器要尽量贴近用户视角**。`text=...`、`button:has-text(...)`、`role` 选择器优于 CSS class —— 后者会随重构而变,前者跟"这个按钮叫什么"绑定。
- **conditional render 是 e2e 的好朋友**。"按钮变文字"比"出现某个文本"更确定。
- **webServer 的 reuseExistingServer 在调试时是救命草**。本地手动起服务,改完 spec 立刻跑 `pnpm e2e`,不用每次重启服务。
- **CI 上要把 reuseExistingServer 关掉**(`reuseExistingServer: !process.env.CI`),保证容器内独立启服务。我们 V1 暂时简化处理,V2 上 GitHub Actions 时再调。
- **数据隔离不是 nice-to-have**。e2e 用唯一 slug 是 V1 的简化方案,V2 / Final 应该让每个测试用独立 DB schema。
