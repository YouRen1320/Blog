# V?-NN <任务标题>

**日期**:YYYY-MM-DD
**任务**:对应 TaskList 里的编号
**状态**:进行中 / 已完成

## 目标

这个任务要交付什么。一句话讲清楚验收标准。

## 关键决策

逐条列出本任务里做的选择,每条说清楚:
- 备选方案是什么
- 选这个的理由
- 放弃其他方案的理由

如果某个决策影响范围超过这个任务,写成 ADR 放到 `docs/decisions/`,这里只链接过去。

## 实际做了什么

按改动顺序写,每条带文件路径(用 file_path:line 形式更好)。
不需要逐行讲解代码,只讲改了什么、为什么需要这个改动。

## 踩坑 / 注意

实际跑代码时遇到的问题、奇怪的报错、文档没说但必须知道的细节。
这是 journal 里最有价值的部分,因为代码本身藏不住这种信息。

## 验收记录

跑了什么命令,看到什么结果。粘贴关键输出。

## 给学习者的提醒

如果你想自己重做一遍这个任务,有哪些点容易忽略、哪些是常见错误来源。
