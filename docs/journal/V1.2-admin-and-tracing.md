## 关键决策

### 1. 改密码不强制踢人

最干净的"改密码"语义是:换完后旧 token 全部失效。但实现路径有两条:

- **JWT 加 jti 黑名单**:每签一个 token 带唯一 jti,登出/改密码时把 jti 写黑名单,中间件每个请求查 Redis。代价:多一张表 + 一个缓存 + 多一次每请求 lookup
- **Secret 轮转**:改 `JWT_SECRET` 重启服务,所有 token 立刻失效。代价:全员重登,失去所有未保存草稿的 sessions

单人博客这两条都不划算。最终选**保留当前 token 有效 + UI 提示用户重新登录**。把决策交还给人。如果用户角色未来扩展到多 user,再上 jti 黑名单也来得及。

### 2. backfill 串行 + 同步

为什么不并发:
- BGE 在 ai-service 单实例,FastAPI 默认 single-worker,**并发请求只是排队**
- 串行更好做错误处理(每篇独立 try/catch,失败不污染整批)

为什么不进任务队列:
- 当前文章数 = 1。100+ 篇时上 BullMQ + SSE 进度推送是直接的演进路线
- 同步同一个 HTTP 请求里跑完,前端 axios timeout 给 5 分钟,**够用**

如果哪天需要异步 + 进度,接口本身可以保持向后兼容(返回 `{ jobId }` 而不是 `{ total, processed, failed }`,前端轮询 `/jobs/:id`)。

### 3. LangSmith 走环境变量,不引代码

LangGraph 的 langchain-core 在 import 时就检测 `LANGCHAIN_TRACING_V2`。开关控制权完全在 ops:

- **关闭时**:`langsmith` 库虽然装了(langchain-core 间接依赖),但**不会发任何请求**,性能 0 影响
- **开启时**:不需要 redeploy 代码,改 env 重启容器即可

Code 完全无侵入。这是 LangSmith 设计的优雅之处。

### 4. 改密码 endpoint 不挂 `/admin`

`/auth/password` vs `/admin/auth/password` 选前者:**任何认证用户都该能改自己密码**,跟"是不是 admin 角色"无关。挂在 `/auth/login` 旁边语义统一。

### 5. 路由顺序:具体路径在前

```ts
@Post('backfill-embeddings')   // 在前
@Post()                        // 在后(create)
@Patch(':id')                  // 动态参数路由放最后
```

虽然 method 不同实际没冲突(POST vs PATCH),但按"具体路径在前"原则放规整,以后加 `@Get('backfill-status')` 之类的也不需要重排。

## 踩坑

按时间顺序:

1. **服务器 git pull 又超时**:GitHub 在境内对长链接非常飘,这次 `Failed to connect to github.com port 443: 连接超时`。用 `tar | scp | tar -xzf` 把改动文件(33 KB)同步过去,2 秒搞定。沿用 V1.1 时的踩坑教训。
2. **prettier 自动重格式化**:跑 `pnpm test` 时某个 hook 把 23 个无关历史文件 prettier 重排了。功能等价但 diff 嘈杂。处理:**单独一个 `chore: prettier format` commit**,跟 feature commit 分开,审 PR 容易。
3. **`articles.controller` 注 `EmbeddingService` 时模块没改**:第一直觉是要在 ArticlesModule 的 `imports` 里加 EmbeddingModule。但 EmbeddingModule 是 `@Global()`(V1.1 当时为了 articles + ai 两个模块都能用),所以直接 inject 就行,不需要改 ArticlesModule。
4. **同密码 + 当前密码错的 endpoint 验证**:不能在生产真改 admin 密码(会破坏后续 SSH/API 链路),所以验证只跑 401/400 路径,**200 路径靠 jest 单测覆盖**。这是"破坏性测试要在隔离环境"的标准实践。
5. **`.env.example` 被 .gitignore 吞**:`.gitignore` 第 2 行 `.env.*` 太宽,把 `.env.example` 一并 ignored,所以我加的 LangSmith 注释只在本地有效。**不修这个**(怕暴露历史 .env.* 内容),改在 `scripts/server-init.sh` 里同步,反正服务器走的是这个模板。

## 学到的

- **写 endpoint 之前先想清楚 401 / 400 / 403 / 200 各自的语义**:改密码这种 endpoint 容易被 401(当前密码错) vs 400(规则错,例如新旧相同) vs 403(不该有,因为认证用户都能改) 搞混。先列出 4 种状态再写代码,不会反复改 status code
- **OpenAPI/Swagger 装一下**:每加一个 endpoint 手写 curl 验证太累。下一版接 nestjs/swagger 直接出文档 + 自动生成 ts client
- **生产做破坏性测试要二次确认**:本来想直接改 admin 密码再改回来,克制住了 —— 改两次密码 = 4 次 API 请求,strict 限流 5/min,踩到 429 整个 admin 自己都登不进去 30 秒。改成只跑 401/400 + 单测覆盖 200。
- **prettier 不该在 jest 期间触发**:这个是项目级 hook 配置问题,留给以后修
- **LangSmith / OpenTelemetry 这种 tracing 框架越来越强**:不修代码就能拿到完整 trace,部署时打开就行。可观测性的成本边际成本越来越低,默认开就好(这次默认关只是因为没 API key,有了就开)
