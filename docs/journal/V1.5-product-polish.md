**日期**:2026-05-05
**任务**:#66 ~ #70
**状态**:已完成
**Tag**:v1.5.0

> 用户问"v1.5 后面做什么",我推荐"让博客真的能用,而不是工程很顶但产品空的"。
> 4 件事 + 1 个 bonus + 1 个磁盘清理。

## 选这四件的逻辑

V1.4 把 AI-native 工程能力补全了(streaming / 多模型 / reranker / eval / OTel / checkpoint / e2e),
但**博客本身**还差几个产品级功能。从"是否能让博客真的好用"维度排:

| 必做 | 理由 |
| --- | --- |
| 图床/封面上传 | cover 字段只能填 URL,博客主基本不会用,不补功能空着 |
| Whisper | mobile 已有 mic 占位,接通它一头 multimodal,比"留 v2.0"实在 |
| OpenAPI | 每加 endpoint 不用手写 curl,加一次终生受益 |
| 评论 AI 辅助 | 已经有 LiteLLM,顺手做 |

## 关键决策

### 1. 图床本地存储,不上对象存储

权衡:

| 方案 | 优势 | 劣势 |
| --- | --- | --- |
| **本地磁盘 + Caddy 反代**(选) | 0 第三方账号 / 0 月费 / 简单 | 单点 / 没 CDN / 跟容器同寿命 |
| Cloudflare R2 | 免费 10GB / 全球 CDN | 要 Cloudflare 账号,初期没必要 |
| AWS S3 | 标准 / 工具齐全 | 要 AWS 账号 + 国内访问慢 |
| 自建 MinIO | 完全控制 | 占 ECS ~200MB 内存,2GB 实例承不起 |

单人博客每月几十张图,本地存 + Caddy 出就够。docker volume 持久化让容器 rebuild 不丢图。
要换 R2 时改 multer storage 一行,代码已经分层。

### 2. /uploads/* 路径放 web 子域,不放 admin

web 端公开访问,文章页 `<img src="/uploads/...">` 要直接出。Caddy 配 `handle /uploads/* → api 容器`,
admin 跨子域引用时用 `resolveCoverUrl()` 拼绝对 URL。

### 3. JwtAuthGuard 加 PUBLIC_PATH_PREFIXES

ServeStaticModule 的请求没有 controller handler,Reflector 拿不到 IS_PUBLIC_KEY,
所以 guard 默认会拦下匿名访问 /uploads/*。修法:guard 顶部按 path 前缀放行
(`/uploads/`、`/healthz`)。比改 ServeStaticModule 配置干净。

### 4. Whisper 完全独立配置(WHISPER_*)

不复用 LLM_PROVIDER 的 key,因为:
- MiMo / Anthropic / Gemini 都没 audio API,复用没意义
- OpenAI Whisper 是行业标准,有专用 key 更清晰
- DashScope paraformer 也走 OpenAI 协议(WHISPER_API_BASE 切一下)

### 5. 录音 m4a aacLc 16kHz

Whisper API 推荐输入。Mobile record package 一行参数搞定。
文件大小 ~20KB/秒(一段 10s 录音 ~200KB),上传快。

不用 wav(没压缩,3MB/分钟太大)/ mp3(LAME 编码额外开销)。

### 6. OpenAPI 走自动反射

不写 `@ApiProperty` / `@ApiOperation` —— **当前 controller + DTO + class-validator 信息已足够**,
反射出来的 OpenAPI 定义包含 path / method / DTO 字段类型 / 校验规则,够用。

要更精细描述时再加装饰器,**别一次性补全所有 endpoint**(那是 LSP 工程文化,不是博客)。

### 7. AI 审核只建议不自动

LLM 误判风险:
- false positive(把好评论判成垃圾)→ 用户体验受损,博客主感知不到
- false negative(垃圾被判成好)→ 漏一些垃圾不致命

考虑误判代价不对称,**AI 永远只给建议**,ADMIN 拍板。这跟内容审核一般原则一致(YouTube/Twitter 也是
机器筛选 + 人工最终决定)。

## 踩坑

1. **Buffer 不直接喂 Blob**:Node 22 lib.dom 的 BlobPart 不接 Buffer 类型,要 `new Uint8Array(buffer)` 转一下,虽然 Buffer 是 Uint8Array 的子类型(运行时兼容,只是 TS 拒绝)
2. **mac 资源叉 `._foo` 文件**:tar+scp 时 macOS 会带 AppleDouble metadata 文件,服务器侧 git 看到全是 untracked。`find . -name "._*" -delete` 清掉
3. **磁盘 94% 满**:V1.4 多次 build 累积 docker layer + 4GB swap + 多版本 node_modules,**需要 prune**
4. **SSH banner exchange 卡**:并发多个 SSH 时 sshd `MaxStartups` 默认 10:30:100,`pkill -9 ssh` 清掉旧进程后才能重连

## 学到的

- **"工程能力"和"产品能力"是两件事**:V1.4 八个工程能力做完后,博客还是不能上传图。要警觉自己别陷入"工程主义"
- **最少改动"接通"占位**:Mobile mic 按钮在 V3 阶段就放了占位,V1.5 用 ~50 行 dart 接通。**不要等到"完美时机"做新功能,占位 → 接通 → 优化 三步走**
- **OpenAPI 反射模式比手写更值**:写完 setup 5 分钟 → 自动出文档 + 浏览器交互。如果当时为了"完整描述每个 endpoint"补全 `@ApiProperty`,半天就过去了,过早优化
- **AI 审核不是终审**:LLM 误判代价不对称(false positive 比 false negative 烦),设计上**永远只给建议**,留给人决定
- **服务器小内存 / 小硬盘要主动清理**:每次 build 前 `docker system prune -af` 是常规动作。CI 里也应该加
