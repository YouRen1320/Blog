## 关键决策

### 1. 不引入 LangChain 主仓库,只装 LangGraph + langchain-core
LangChain 主仓库 1000+ 个集成包,过度抽象、API churn。LangGraph 是它的 stateful agent 子项目,可以单独用 + 类型清晰。

### 2. 本地 BGE 不用第三方 embedding API
- 中国境内访问 OpenAI / Voyage 不稳
- 小米 MiMo 是 Claude 协议(只有 messages 没 embeddings)
- 阿里云 dashscope 要单独 key + 收费
- BGE-small-zh-v1.5 是开源模型,fastembed 用 ONNX 跑 100MB / CPU 推理 < 100ms
- **不烧 quota,中文好,首次部署多 100MB 镜像**

### 3. 直接 psycopg + raw SQL,不用 SQLAlchemy ORM
- ai-service 只 SELECT + 比较向量,逻辑非常简单
- 引 ORM 多一层抽象、多一份 schema 来源
- **psycopg + pgvector 库 + cosine `<=>` 操作符,30 行代码搞定**

### 4. embedding 在 publish 后异步触发
`void this.embedding.embedArticle(id)`(没 await),用户的 publish 接口不被 RAG 索引拖慢。失败时只 warn,后续可以批量补。

### 5. 同一份 admin SPA 镜像走生产/开发
- baseURL 运行时探测 `window.location.hostname`
- 不需要给生产 build 单独传 build arg
- 镜像跨环境复用,CI 简单

## 踩坑记录

1. **BGE-small-zh-v1.5 输出 512 维,不是 384**(常以为 small=384)。Schema/Migration 错过一次,改了
2. **macOS Python 3.14 太新**,fastembed 的 transitive `py-rust-stemmers` 没 wheel,需要 Python 3.12 venv
3. **fastembed HuggingFace 下载默认走 huggingface.co**,中国境内不稳,要 `HF_ENDPOINT=https://hf-mirror.com`
4. **Dockerfile 预下载模型**:`RUN python -c "..." | tail -3` 把错误吞了,导致 cache 没下到。后来去掉 pre-download,改成运行时下载
5. **服务器 git pull GitHub 还是不稳**,关键改动用 `tar | scp` 替代
6. **Debian trixie 用 DEB822 sources.list.d**,sources.list 写了不读
7. **生产 admin SPA baseURL 没 build arg 注入**:这是用户实际遇到的"登录报错"的原因,本次报告里有详细修法
