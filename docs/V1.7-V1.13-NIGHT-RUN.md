## 关键决策

### 1. 评论 Gravatar:hash 在 service 算,API 不返 email

担心 email 泄漏(垃圾邮件 / 隐私)。`publicCommentSelect` 在 service 内部带 email,`toPublic()` mapper 算完 md5 直接 drop email,**web 端永远拿不到原始邮箱**。

### 2. 嵌套用 flatten + depth padding,不抽递归组件

Vue 3 SFC 不支持组件自引用(需要 named export),抽递归组件成本高。flatten 后 `<li>` 平铺 + `padding-left: depth * 24px`,DOM 简单 + DFS visit 顺序天然父在前子在后。

### 3. dashboard 单 endpoint 不分散

不做 `/admin/stats/articles` `/admin/stats/comments` 等多 endpoint。用户进 dashboard 一次 fetch 拿全部,前端渲染 7 个卡。**少 6 个 round trip**,首屏更快。

### 4. AI 标签流末解析,不流式渲染

LLM 输出 `"标签1, 标签2, 标签3"` 流式来时 partial split 会闪烁(逗号边界不稳定)。**等流末统一处理**,`acc.split(/[,，]/)` 一次性。

### 5. 用户删除规则:名下有文章不能直删

考虑过 `onDelete: Cascade`(删用户 + 文章一起删),但这不是博客该有的语义 — 用户离开但文章应该保留(也许转给 admin 接管)。规则:**先迁移文章再删用户**,前端给清晰的 conflict 提示。

### 6. 全文搜索用 ILIKE,不上 pg_jieba

中文分词需要 pg_jieba 扩展(C 编译,Aliyun Linux 上装麻烦)+ 词典几十 MB。当前文章数 < 100,ILIKE 性能完全够。**等文章数到 1000+ 再考虑**。

### 7. 拖拽图片串行上传,不并发

多张图片粘贴时,**`for await` 串行处理** 而非 `Promise.all`。原因:
- 防止同时几个请求挤爆 NestJS multer
- 串行时光标位置追踪简单(每张插入后光标移到插入后,下一张继续)
- 单图片 ~2s,3-5 张 = ~6-15s 用户感知合理

## 踩坑

1. **Bash heredoc 含 `$()` 嵌套语法错**:验证 stats endpoint 时复杂的 SSH 嵌套子命令解析失败,改用 `\$()` escape + 单引号包裹外层
2. **docker compose up -d 不自动用新 image**:image tag 不变 docker 不知道要重启,用 `--force-recreate --no-deps web admin` 强制
3. **流式 chunk 累积进 textarea 闪烁**:title/summarize/tags 每行都不一样的处理方式,tags 不流式渲染解决
4. **`@nestjs/serve-static` 跟 JwtAuthGuard 冲突**(V1.5 踩过):路径前缀 `/uploads/` 单独放行,这次 stats / search 路径都加了 @Public 或 @Roles 没再踩

## 凌晨节奏自评

- **每件事独立 commit + push**:夜里 7 个 commit,GitHub 看时间线清晰
- **build / test 不跳过**:每次 push 前 admin/web/api build 都过,17/17 jest 全过
- **没冒架构险**:Modern stack 重写 / Serverless / 多模态 这些大改造没碰
- **服务器 OOM 后用单服务串行 build 部署**:磁盘从 99% → 47% 后稳健
