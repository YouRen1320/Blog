## 关键决策

### 1. 流式输出走 free-form markdown 而不是 streaming tool calling

OpenAI 协议**理论上**支持 streaming + tool calling(tool_call.arguments 是 partial JSON),但解析 partial JSON 在 v1 阶段成本不值得。改让 LLM 输出"约定格式的 markdown"(`# 标题 / > 摘要 / 正文 / tags:`),流末 regex parse 一次性提取。

### 2. 内联 AI 流式 chunk 累积用 before/after 固定法

不算 offset(每来一 chunk content 长度变,offset 算错就错位)。**流前固定 beforeContent/afterContent,chunk 来时只更新中间 acc**。简单且正确:
```ts
post.content = beforeContent + acc + afterContent
```

### 3. LiteLLM + LangFuse 都是 0 侵入接入

业务代码完全不知道在不在追踪。这是 modern AI-native 工程的最佳实践:**可观测性靠 callback / instrumentation,不靠业务侧手写 log**。

### 4. Reranker 选 BGE-reranker-base 而不是 jina-tiny

中文友好 + 1GB 可接受。如果生产嫌大,文档有降级路径(jina-v1-turbo 150MB)。

### 5. checkpoint 选 MemorySaver 而不是 SqliteSaver

简单 + 无状态依赖。代码注释里写了 Sqlite 切换方法,需要时几行改完。

### 6. e2e 改密码只测错路径

200 路径靠 jest 单测,e2e 不真改 admin 密码 —— 否则后续 e2e 全部登录失败,strict 限流 5/min 还会踩到 429。

### 7. promptfoo 锁定 0.119.0

最新 0.121.x 要求 Node 22.22+,本地是 22.14。**锁版本而不是升级 Node** —— 升 Node 是环境改动,影响别的项目。

## 踩坑

1. **Tailwind oxide UTF-8 panic 之后又来一个 Prisma client 路径变 bug**:装 OTel 包让 pnpm 重链 node_modules,Prisma generated client 路径 hash 变了。修法:`prisma generate` 再跑一次
2. **YAML 隐式 `TAGS:`**:promptfooconfig 里 `value: TAGS:` 让 YAML parser 以为是 nested mapping,改成 `value: 'TAGS:'`
3. **better-sqlite3 native binding 跟 Node 22.14 不匹配**:`npm rebuild` 修
4. **promptfoo 0.121+ 要求 Node 22.22+**:锁 0.119.0
5. **type intersection 不被 NestJS reflect**(V1.3 已记):再次提醒别用,DTO 必须 class extends
6. **编辑器旧 bug**:title 校验缺失 + 新建态发布只 save 不 publish。已修
